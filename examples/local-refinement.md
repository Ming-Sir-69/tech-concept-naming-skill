# 一次局部修改会怎样发生

下面是**演示对话**，用于说明产品交互，不是新增真实用户案例，也未进行名称占用或词源检索。

**用户**：给一个解释代码修改的 AI CLI 命名，面向开源维护者。不要自动改代码。中文独立构思。

**Agent 应先确认理解**：核心是把修改整理成便于审阅的解释，而不是自动写补丁。候选可以从“编织修改”“看清差异”等不同概念探索，例如 `Patchweft / 补织` 与 `Diffview / 观差`。这些是现代英文组合的示范名称，不应包装成古代词语；词义与占用检查尚未进行。

**用户**：保留 Patch，只改后半段；中文先不动。不要 bot。

**Agent**：可将 `Patch + weft` 改为 `Patch + loom → Patchloom`。保留 Patch、中文补织和 bot 排除；解释也需要改成当前组合，不能继续把已删除的 weft 当成构词成分。

**用户**：撤回 bot 排除，其他决定保留。暂时用 Patchloom。

**Agent 应交付**：当前英文 Patchloom、中文补织、确切组成 Patch + loom、仍保留 Patch 的偏好，以及已撤回的 bot 排除。说明这是暂定方案，名称占用尚未查询；此时停止继续批量生成。

是否使用 helper 取决于实际收益。短对话可以直接记住决定；需要精确词段历史或跨会话续接时，参见 [可执行状态示例](../docs/state-helper.md)。两条路径都应保留用户已认可的选择。
